# Core Concepts

## What Is an Engram?

An **engram** is a discrete unit of reasoning memory -- a neuroscience term for a memory trace stored as a biophysical change in neural tissue. In Engram, it's the complete record of an AI agent session linked to one or more git commits.

An engram answers the question that a git diff cannot: **Why does this code look like this?**

## The Five Components

Every engram contains five files stored as Git objects:

### Manifest (`manifest.json`)

Compact metadata for fast listing and filtering. Contains:

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | UUID v4 hex (32 characters, no dashes) |
| `version` | integer | Schema version (currently 1) |
| `created_at` | ISO 8601 | When the session started |
| `finished_at` | ISO 8601 | When the session ended (optional) |
| `agent.name` | string | Agent identifier (e.g., "claude-code") |
| `agent.model` | string | Model used (e.g., "claude-sonnet-4-5") |
| `git_commits` | string[] | Commit SHAs produced during this session |
| `token_usage.input_tokens` | integer | Tokens sent to the model |
| `token_usage.output_tokens` | integer | Tokens generated by the model |
| `token_usage.total_tokens` | integer | Sum of all token fields |
| `token_usage.cost_usd` | float | Estimated cost in USD |
| `summary` | string | One-line summary of what was done |
| `tags` | string[] | User-defined tags |
| `capture_mode` | enum | `"wrapper"`, `"import"`, or `"sdk"` |

### Intent (`intent.md`)

Human-readable Markdown describing the reasoning behind the session:

- **Original request** -- What the human asked for, in their words
- **Interpreted goal** -- How the agent understood the request
- **Dead ends** -- Approaches that were tried and rejected, with reasons
- **Decisions** -- Architectural choices made, with rationale

### Transcript (`transcript.jsonl`)

The full session transcript, one JSON message per line:

```json
{"timestamp": "2026-02-16T10:30:00Z", "role": "user", "content": "Add OAuth2 auth"}
{"timestamp": "2026-02-16T10:30:05Z", "role": "assistant", "content": "I'll implement..."}
```

### Operations (`operations.json`)

What the agent actually did:

- **Tool calls** -- Each tool invocation with input, output, duration, and error status
- **File changes** -- Files created, modified, or deleted with line counts
- **Shell commands** -- Commands executed with exit codes and duration

### Lineage (`lineage.json`)

Relationships to other entities:

- **Parent engram** -- The engram this one continues from
- **Child engrams** -- Engrams that follow from this one
- **Git commits** -- Commit SHAs produced during this session
- **Branch** -- The Git branch this session was on

## Storage Model

Engrams are stored as **native Git objects** -- not files on disk, but blobs, trees, and commits inside the `.git` directory. This means they travel with `clone`, `push`, and `pull` automatically.

### Ref Layout

```
.git/refs/engrams/
  <ab>/                    # First 2 chars of ID (fanout)
    <full-id>              # Points to a commit object
```

Each ref points to a commit, which points to a tree containing the five component files:

```
ref (refs/engrams/ab/abc123...)
  └── commit (orphan, no parent)
       └── tree
            ├── manifest.json
            ├── intent.md
            ├── transcript.jsonl
            ├── operations.json
            └── lineage.json
```

Engram commits are **orphan commits** -- they have no parent and are not on any branch. They exist as standalone objects in the Git object store, referenced only by engram refs.

### HEAD Pointer

Engram maintains a `.git/engram-head` file that points to the most recently created engram, enabling fast `engram show HEAD` resolution without scanning all refs.

## Four Capture Modes

| Mode | How It Works | Best For |
|------|-------------|----------|
| **Automatic** | `engram init` installs Claude Code hooks. Sessions auto-imported on exit and on commit. | Claude Code users (zero effort) |
| **Wrapper** | `engram record -- <command>` spawns the agent in a PTY, captures output, detects file changes via SHA-256 snapshots | Any agent, zero integration effort |
| **Import** | `engram import` parses existing session files (Claude Code JSONL, Aider markdown) | Retroactively capturing past sessions |
| **SDK** | Call `EngramSession` API directly from your agent code | Maximum data quality and control |

### Choosing a Mode

- **Use Automatic** if you use Claude Code -- just run `engram init` and everything works
- **Start with Import** if you already have Claude Code or Aider sessions -- get value immediately from past sessions
- **Use Wrapper** for agents that don't have SDK integration yet
- **Use SDK** when you control the agent code and want the richest data (structured tool calls, explicit dead ends, accurate token counts)

## Git Notes

Engram attaches rich reasoning metadata to commits as [git notes](https://git-scm.com/docs/git-notes) under `refs/notes/engram`. Notes are automatically attached when:

- The Claude Code `SessionEnd` hook fires (auto-annotate)
- You run `engram init` (annotates existing linked commits)
- You run `engram annotate` (manual, supports ranges and `--force`)

View with `git loge` (alias installed by `engram init`) or `git log --notes=engram`.

## Cost Estimation

Even when agents don't report costs directly (e.g. Claude Code imports), engram estimates costs at display time using model name + token counts + built-in API pricing tables. Supports Claude, GPT-4, and o1/o3 model families with cache-aware pricing. Explicit cost data takes priority when available.

## Search Index

Engram maintains a full-text search index (powered by Tantivy) at `.git/engram-index/`. The index is:

- **Auto-created** on first search
- **Incrementally updated** when creating or importing engrams
- **Fully rebuildable** with `engram reindex`

Indexed fields: summary, intent, transcript content, file paths, agent name, tags.

## Context Graph

Engrams form a **context graph** -- a semantic reasoning layer over your codebase:

- **Nodes**: engrams, files, agents, commits
- **Edges**: "modified by", "used agent", "follows from", "touched file", "produced by"

Explore with `engram graph` or export as Graphviz DOT format.
